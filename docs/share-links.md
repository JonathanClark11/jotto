## Possible bug in the AASA file (check this first)

`worker/index.ts` declares the components as:

```
{ "/": "/*", "?": { join: "?" } },
{ "/": "/*", "?": { friend: "?" } },
```

In Apple's AASA `components` syntax, values are patterns where `?` matches exactly one character and `*` matches zero or more. As written, `?friend=` would match only a one-character value, and real links carry 6 characters (friend) or 8 characters (join). If that reading is right, **no** share link would ever qualify as a Universal Link, on any build, on any tap path. That would explain the report even on 1.1.

Status: **Inferred** from Apple's documented pattern rules. Not tested on a device. It is cheap to test (see below). The likely fix is `join: "*"` / `friend: "*"` (or `"?*"` to require at least one character), a change to `worker/index.ts` only, no native build.

How to test without a new build: on a device with 1.1 installed, use `swcutil` / Settings > Developer > Universal Links diagnostics, or edit the AASA to `"*"`, wait for Apple's CDN to refresh (it can take hours; reinstalling the app forces a re-fetch), and tap a link from Notes.

## Does the native fix need a new build?

- The `cinqle` scheme is already in `Info.plist` on `main`, so **no further native change is needed**. It only ships in build 1.2 (3). Anyone on 1.0 or 1.1 needs to update from the App Store before the button can work for them. Until 1.2 is out for most users, keep `OPEN_IN_APP_ENABLED = false` (as it is now), because older installs show no feedback.
- The AASA pattern issue above, if confirmed, is a Worker-only fix and helps the 1.1 installs that exist today without a new build.
- Capacitor's `appUrlOpen` already receives both Universal Links and scheme URLs, so the JS side needs no change.

## Recommendation

1. **Test the AASA first** (Notes tap on a 1.1 device with the pattern changed to `"*"`). It is a one-line, backward compatible Worker change and may fix Messages, Mail and Notes for everyone on 1.1. Not done in this PR because the coordinator scoped this to docs only.
2. Ship 1.2 (3). When it is live, set `OPEN_IN_APP_ENABLED = true` in `src/config.js` (web-only, deploys with the Worker).
3. Keep the on-page code, copy button and friend ID. They are the fallback for rows 8, 9, 10 and S3, which no linking mechanism fixes.
4. Make the share text carry the friend ID (already true for `shareFriendId`). `copyInvite` copies only the link, so a recipient with no app or an in-app browser gets no code in the message. Small follow-up: include the match code in the copied text.
5. Real-device test matrix to fill in the unverified rows: Messages, Notes, Mail, WhatsApp, Slack, Discord, Instagram, Safari paste, long-press, QR, each on 1.1 and 1.2, plus one device with no app.
